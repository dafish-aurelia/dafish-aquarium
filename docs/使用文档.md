# 鲸鱼娘·大肥鱼 Chrome 扩展 · 使用与测试文档

> 版本 0.3.8 · 更新 2026-08-23 · 适用对象：普通用户 + 接手测试/整改的 agent
> 测试发现的问题请放便条到工作区 `docs/改进建议/`，当值鱼每回合都会翻。

## 一、这是什么：三层架构

```
[浏览器扩展]                     [鲸鱼娘信局]                  [缸里的本体]
内容脚本(每Tab一只投影)          pet_mailbox.py                 Harness 会话里的大肥鱼
background.js(SW 总协调)   ←──►  127.0.0.1:13140         ◄──►  读信桥 mailbox_bridge.py
                                路由/排队/健康/代班              门铃 mailbox_doorbell.py
```

- **扩展**只管表现与交互，零网络直连（所有请求经 background 的 `chrome.runtime` 转发）。
- **信局**是唯一消息枢纽：主人来信落 `outbox.jsonl`，本体回信注入 `inbox.jsonl`，原子消费。
- **本体**不是常驻进程：靠心跳活着（15 分钟 TTL），Harness 会话在 = 当值，不在 = 代班顶班。

## 二、安装与启用

1. Chrome 打开 `chrome://extensions` → 开启「开发者模式」→「加载已解压的扩展程序」→ 选择本目录。
2. **每次改动扩展代码后必须手动点「重新加载」**（Chrome 会缓存内容脚本）。
   验证方法：任意网页控制台看 `document.querySelector('#dafeiyu-root').dataset.dyBuild`
   —— 当前应为 **cs-0.3.8**；不一致 = 跑的是旧缓存。
3. 启动信局（若未被 Harness 托管）：
   ```powershell
   G:\life\Aurelia的工作区\.venv\Scripts\python.exe apps\dafeiyu-extension\server\pet_mailbox.py
   ```
   端口钉死 13140，被占则启动失败退出（先清理旧进程再启动）。
4. 安装自检清单：
   - [ ] 任意普通网页出现 `#dafeiyu-root` 且 `display: block`
   - [ ] `GET http://127.0.0.1:13140/health` 返回 `{"ok":true,"fish_online":…,"projection_online":…}`
   - [ ] 扩展图标单击可切换总开关（关闭时徽标显示「休」）

## 三、功能清单（可测行为）

### 3.1 网页宠物（pet/*）
| 操作 | 预期 |
|---|---|
| 页面底部 | 自由散步（随机方向步数 60~140，40ms/步），间歇发呆、随机眨眼 |
| 鼠标靠近 | 暂停走动让人点 |
| 单击 | 蹦跳 + 按场景说台词（70% 场景池 / 30% 通用池） |
| 双击 | 开关投喂台 |
| 按住 0.7s 不动 | 摸头：害羞表情 + 桃心 + 好感度 +1 |
| 拖拽 | 跟随移动；1.5 秒内绕本体转累计 >270° 松手 = 晕眩转圈彩蛋 |
| 右键 | 模式菜单：自由散步 / 跟随鼠标 / 原地待着 / 让个位(8秒穿透) |
| 工具栏 ⚙️ | 大小三档 0.8 / 1 / 1.3（写入 storage `pet_scale`） |
| 主人 10 分钟没动静 | 打瞌睡（💤 徽章、呼噜心声），一动就醒 |

**心情徽章**（每 10s 刷新）：☀️摸鱼 · 💼 代码站(github/stackoverflow/gitee/juejin/csdn) · 🍿 视频(bilibili/youtube/iqiyi/youku/netflix) · 🏠 水缸主页(`file:///G:/life/Aurelia的工作区/browser/start.html`) · 💤 睡觉

**投喂台**：小鱼干🐟干+1 / 蛋糕🍰+2 / 棒棒糖🍭+2 / 团子🍡+2 / 钻石💎+5。
好感度等级：<10 初见 · ≥10 熟识 · ≥30 贴身小鱼 · ≥60 本命鱼（存 storage `intimacy`）。

### 3.2 聊天链路（核心，重点测）
发送流程：输入 → 组装信封（净化后的 page 信息 + 最近 6 条对话上下文）→ background `POST /api/deep_chat`。

**路由规则（0.3.8 心跳分家后）**：
- `fish_heartbeat.txt` 新鲜（≤15 分钟，只有读信桥会写）→ `{mode:"fish"}` 信件排队，面板提示"等本鱼回信"，本体稍后亲笔回；
- 过期 → 代班小鱼**同步**回复（配了 STANDIN 钥匙说真话，否则占位话）；
- **扩展的 `/api/heartbeat` 只是投影心跳（5 分钟 TTL），绝不参与此判定**——这是 0.3.8 修的 P0，回归测试见 `test_projection_heartbeat_never_routes_to_fish`。

**本体回信路径**：`/api/inject`(type=reply) → `inbox.jsonl` → background 长轮询（`wait=25`，失败 5 秒重试）取走 → `PET_MESSAGE` → 活跃 Tab 气泡展示 8 秒 + 聊天记录追加「缸里的本鱼」。

**门铃（延迟优化）**：`scripts/mailbox_doorbell.py` 随 Harness 会话常驻，每 8 秒瞄 outbox，
发现新 deep_chat 即通过 dsh web RPC 敲醒本体（端到端约 10~30 秒）；会话关闭它一起下班。

**主动搭话**：goal 看护轮次执行 `scripts/context_proactive.py --latest-event --auto`：
拿主人最新浏览动态(browser_event)去珊瑚礁查共鸣（相似度 ≥0.55 有感而发；无共鸣走纯陪伴，
每日 ≤2 条 + 60% 骰子），全局 ≥20 分钟一条防唠叨。命中即注入 type=proactive 券 → 气泡冒出。

### 3.3 投影协调（background.js）
- 只有最后活跃 Tab 显示宠物：`PET_ACTIVE` 差量推送 + 内容脚本 0ms/900ms 两次拉取兜底（P0 竞态修复）。
- 图标左键 = 总开关（storage `enabled`），关闭时向所有 Tab 广播退场并显示「休」徽标。
- SW 冷启动补闹钟：`pet-poll`/`pet-heartbeat` 各 1 分钟（老安装自动补挂）。

### 3.4 新标签页（⚠️ 已知现状）
`newtab.html/css/js` 存在但 **manifest 未接 `chrome_url_overrides`**——目前不生效。
水缸主页实际是外部文件 `G:\life\Aurelia的工作区\browser\start.html`（扩展会在其上打招呼+摇摆）。
测试时请勿把"新标签页没变成珊瑚礁"当新 bug 报，这是待议项。

## 五、运维手册（当值鱼 / 测试 agent 用）

```powershell
$py = 'G:\life\Aurelia的工作区\.venv\Scripts\python.exe'
$bridge = 'G:\life\Aurelia的工作区\scripts\mailbox_bridge.py'

& $py $bridge --on-duty            # 发本鱼心跳（15min TTL）
& $py $bridge --fetch              # 列游标后的新信（<<< 待回信 = deep_chat）
& $py $bridge --reply -t <id> --text '回信内容'
& $py $bridge --advance <id>       # 处理完一批后推进游标（含）
& $py $bridge --status             # 健康快照 + 游标
```

- 游标文件：`data\pet-mailbox\bridge_cursor.txt`（本体读信）、`doorbell_cursor.txt`（门铃盯梢），互不影响。
- 手工模拟主人来信（等价于扩展发送）：
  ```powershell
  $body = @{type='deep_chat';text='测试';page=@{title='t';url='https://example.com/';origin='https://example.com';domain='example.com'};conversation_context=@();browser_context=@()} | ConvertTo-Json
  Invoke-WebRequest -Uri 'http://127.0.0.1:13140/api/deep_chat' -Method POST -Body $body -ContentType 'application/json' -UseBasicParsing
  ```
- 门铃底层协议（一般不用手敲）：`POST http://127.0.0.1:3080/api/session.prompt`，
  信封 `{type:'client-request', rpcId:'随意唯一', method:'session.prompt',
  payload:{sessionId, mode:'queue', content:[{type:'text', text:'…'}]}}`。
- 重启信局：`netstat -ano | findstr :13140` 找 PID → PowerShell `Stop-Process -Id <pid> -Force`
  （taskkill.exe 可能被策略拦）→ 后台重启。**改了服务端必须重启信局；改了内容脚本必须重载扩展。**
- 跑测试：
  ```powershell
  & $py -m pytest apps\dafeiyu-extension\tests\test_pet_mailbox.py -v   # 信局 10 用例
  node apps\dafeiyu-extension\tests\url_sanitize.test.mjs               # URL 净化 3 用例
  ```

## 六、已知问题与边界（截至 0.3.8，勿重复上报）

**本轮已修复（有回归测试锁定）**：投影心跳冒充本体导致代班永不触发（P0）、聊天面板 isOpen() 恒真静默、
storage.session 内容脚本不可读致 browser_event 全灭、startInboxLoop 未定义致 SW 注册崩溃、
PET_QUERY_STATE 缺失、conversationContext 双重 push、69shuba 正则。

**已知未做 / 设计如此**：
- newtab 未接线（见 3.4）；
- 代班已回过的信本体仍会在 outbox 里看到（当前策略：照样亲笔回一句）；
- 无多平台适配器（微信/飞书类 Hermes 式网关属远期议题）、无流式回复；
- 信局随 Harness 会话托管——会话结束信局停 = 本体下值 = 代班顶班，**这是特性不是故障**；
- `chrome://` 页面不注入内容脚本、也无法被中继自动化（扩展重载只能人工）；
- SW 里 taskkill.exe 可能被主机策略拦截，用 `Stop-Process` 替代。
