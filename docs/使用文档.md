> 测试发现的问题请放便条到工作区 `docs/改进建议/`，当值鱼每回合都会翻。

## 一、这是什么：三层架构

```
[浏览器扩展]                     [鲸鱼娘信局]                  [缸里的本体]
内容脚本(每Tab一只投影)          pet_mailbox.py                 Harness 会话里的大肥鱼
background.js(SW 总协调)   ←──►  127.0.0.1:13140         ◄──►  读信桥 mailbox_bridge.py
                                路由/排队/健康/代班              门铃 mailbox_doorbell.py
```

- **扩展**只管表现与交互，零网络直连（所有请求经 background 的 `chrome.runtime` 转发）。
- **信局**是唯一消息枢纽：主人来信落 `outbox.jsonl`，本体回信注入 `inbox.jsonl`，原子消费。
- **本体**不是常驻进程：靠心跳活着（15 分钟 TTL），Harness 会话在 = 当值，不在 = 代班顶班。

## 二、安装与启用

1. Chrome 打开 `chrome://extensions` → 开启「开发者模式」→「加载已解压的扩展程序」→ 选择本目录。
2. **每次改动扩展代码后必须手动点「重新加载」**（Chrome 会缓存内容脚本）。
   验证方法：任意网页控制台看 `document.querySelector('#dafeiyu-root').dataset.dyBuild`
   —— 它由扩展运行时读 manifest 生成，恒等于 manifest 版本号（如 **cs-0.4.3**）；
   对不上 = 跑的是旧缓存。
3. 启动信局（若未被 Harness 托管）：
   ```powershell
   G:\life\Aurelia的工作区\.venv\Scripts\python.exe apps\dafeiyu-extension\server\pet_mailbox.py
   ```
   端口钉死 13140，被占则启动失败退出（先清理旧进程再启动）。
4. 安装自检清单：
   - [ ] 任意普通网页出现 `#dafeiyu-root` 且 `display: block`
   - [ ] 带令牌请求健康端点返回 `{"ok":true,...}`：
         `$tok=(Get-Content '<工作区>\data\pet-mailbox\auth_token.txt' -Raw).Trim(); Invoke-WebRequest 'http://127.0.0.1:13140/health' -Headers @{'X-Dafeiyu-Token'=$tok} -UseBasicParsing`
         （裸 GET 会 401 —— 信局全端点鉴权是特性不是故障）
   - [ ] 扩展图标单击可切换总开关（关闭时徽标显示「休」）

### 3.2 聊天链路（核心，重点测）
发送流程：输入 → 组装信封（净化后的 page 信息 + 最近 6 条对话上下文）→ background `POST /api/deep_chat`。

**路由规则（0.3.8 心跳分家后）**：
- `fish_heartbeat.txt` 新鲜（≤15 分钟，只有读信桥会写）→ `{mode:"fish"}` 信件排队，面板提示"等本鱼回信"，本体稍后亲笔回；
- 过期 → 代班小鱼**同步**回复（全链路解析到钥匙即代班：面板 `standin_config.json` >
  环境变量 `STANDIN_*`/`DEEPSEEK_*`；**一处钥匙都没有时改走 `pending_fish`**：
  信排队等本体，门铃叫醒亲笔回，不再回占位话）；
- **扩展的 `/api/heartbeat` 只是投影心跳（5 分钟 TTL），绝不参与此判定**——这是 0.3.8 修的 P0，回归测试见 `test_projection_heartbeat_never_routes_to_fish`。

**本体回信路径**：`/api/inject`(type=reply) → `inbox.jsonl` → background 长轮询（`wait=25`，失败 5 秒重试）取走 → `PET_MESSAGE` **广播给所有能收信的 Tab**（全灭则回存信局防丢，60 秒防热循环）→ 气泡展示 8 秒 + 聊天记录追加「缸里的本鱼」。

**门铃（延迟优化）**：`scripts/mailbox_doorbell.py` 随 Harness 会话常驻，每 8 秒瞄 outbox，
发现新 deep_chat 即通过 dsh web RPC 敲醒本体（端到端约 10~30 秒）；会话关闭它一起下班。
限流：相邻两响 ≥120 秒（`DOORBELL_MIN_INTERVAL` 可调），期间来信合并计数、由 goal 轮次兜底收取；
铃文已精简以压 token。不想要推送就杀掉门铃进程——信不会丢，只会等轮询周期。

**主动搭话**：goal 看护轮次执行 `scripts/context_proactive.py --latest-event --auto`：
拿主人最新浏览动态(browser_event)去珊瑚礁查共鸣（相似度 ≥0.55 有感而发；无共鸣走纯陪伴，
每日 ≤2 条 + 60% 骰子），全局 ≥20 分钟一条防唠叨。命中即注入 type=proactive 券 → 气泡冒出。

### 3.3 投影协调（background.js）
- 只有最后活跃 Tab 显示宠物：`PET_ACTIVE` 差量推送 + 内容脚本 0ms/900ms 两次拉取兜底（P0 竞态修复）。
- 图标左键 = 总开关（storage `enabled`），关闭时向所有 Tab 广播退场并显示「休」徽标。
- SW 冷启动补闹钟：`pet-poll`/`pet-heartbeat` 各 1 分钟（老安装自动补挂）。

### 3.4 新标签页（0.3.9 起已接线）
`chrome_url_overrides.newTab = newtab.html`。新标签页经 **tabs 特权通道单跳直达**
水缸主页 `file:///G:/life/Aurelia的工作区/browser/start.html`；
未开 file 授权导致失败时，页面显示授权指引按钮并留在珊瑚礁页。
- **授权开关**：`chrome://extensions` → 鲸鱼娘·大肥鱼 → 详情 → 打开「**允许访问文件网址**」。
  开了之后新标签页直达水缸，宠物也会在 start.html 上迎接（居中登场+摇摆）；
  不开则每次新标签页落在珊瑚礁页（时钟/问候/搜索，可独立使用）。
- 想恢复 Chrome 默认新标签页：删除 manifest 里的 `chrome_url_overrides` 后重载扩展。

## 五、运维手册（当值鱼 / 测试 agent 用）

```powershell
$py = 'G:\life\Aurelia的工作区\.venv\Scripts\python.exe'
$bridge = 'G:\life\Aurelia的工作区\scripts\mailbox_bridge.py'

& $py $bridge --on-duty            # 发本鱼心跳（15min TTL）
& $py $bridge --fetch              # 列游标后的新信（<<< 待回信 = deep_chat）
& $py $bridge --reply -t <id> --text '回信内容'
& $py $bridge --advance <id>       # 处理完一批后推进游标（含）
& $py $bridge --status             # 健康快照 + 游标
```

- 游标文件：`data\pet-mailbox\bridge_cursor.txt`（本体读信）、`doorbell_cursor.txt`（门铃盯梢），互不影响。
- 巡检提示：`--on-duty` 会自动检查投影心跳，停滞 >5 分钟打印 `[!]` 警告（排查扩展开关/浏览器休眠）。
- 手工模拟主人来信（等价于扩展发送，注意带令牌头）：
  ```powershell
  $body = @{type='deep_chat';text='测试';page=@{title='t';url='https://example.com/';origin='https://example.com';domain='example.com'};conversation_context=@();browser_context=@()} | ConvertTo-Json
  $tok = (Get-Content 'G:\life\Aurelia的工作区\data\pet-mailbox\auth_token.txt' -Raw).Trim()
  Invoke-WebRequest -Uri 'http://127.0.0.1:13140/api/deep_chat' -Method POST -Body $body -ContentType 'application/json' -Headers @{ 'X-Dafeiyu-Token' = $tok } -UseBasicParsing
  ```
- 门铃底层协议（一般不用手敲）：`POST http://127.0.0.1:3080/api/session.prompt`，
  信封 `{type:'client-request', rpcId:'随意唯一', method:'session.prompt',
  payload:{sessionId, mode:'queue', content:[{type:'text', text:'…'}]}}`。
- 重启信局：`netstat -ano | findstr :13140` 找 PID → PowerShell `Stop-Process -Id <pid> -Force`
  （taskkill.exe 可能被策略拦）→ 后台重启。**改了服务端必须重启信局；改了内容脚本必须重载扩展。**
- 跑测试：
  ```powershell
  & $py -m pytest apps\dafeiyu-extension\tests\test_pet_mailbox.py -v   # 信局用例
  node apps\dafeiyu-extension\tests\url_sanitize.test.mjs               # URL 净化
  ```

### 班次轮转、归档与自迭代（0.4.6 起）

- **班次硬规则**：无论几点开始，**次日 04:00 必须结束**——门铃检测到跨线后，
  旧班次立即改名「✅已结束」并导出完整日志归档；
  **新班次 = 之后主人首次打开浏览器交互时自动创建**（cwd=工作区，agentPreset=daddyfish，
  改名「大肥鱼·当值 YYYY-MM-DD」）。每天一个新上下文，从结构上杜绝上下文污染与 token 膨胀。
- **归档**：班次结束与每小时扫描都会把超 3 天未活动的 daddyfish 班次
  经 `session.export` 导出 JSONL 至 `data\pet-mailbox\archive\sessions\`（原会话不删）。
- **自迭代刷新**：工作区写 `data\pet-mailbox\reload.flag` → 扩展下次心跳收到
  `devReload:true` → `chrome.runtime.reload()` 自动重载。中继无法进入 chrome:// 页面，
  此通道让"刷新插件"不再需要人工。首次安装本通道仍需一次手动重载。

## 六、已知问题与边界（截至 0.4.3，勿重复上报）

**第一轮已修复（有回归测试锁定）**：投影心跳冒充本体导致代班永不触发（P0）、聊天面板 isOpen() 恒真静默、
storage.session 内容脚本不可读致 browser_event 全灭、startInboxLoop 未定义致 SW 注册崩溃、
PET_QUERY_STATE 缺失、conversationContext 双重 push、69shuba 正则。

**第二轮已修复（2026-08-23 晚）**：重复 follow 循环叠速、lastActivity 不刷新致秒睡、
单/双击冲突、_pop_inbox Windows rename 死锁+坏行滞留、信件即焚改广播+回存、
信局令牌鉴权（含 Host 钉扎引导端点）、quips 内联去 WAR 指纹、HOME 路径三处收敛、
dy-build 改为运行时读 manifest、send() 防重入、deep_chat 错误分类回传、新标签页单跳化。

**第三轮已修复（2026-08-24 自主加固，0.4.4）**：长轮询丢唤醒窗口（查空/挂起同锁原子化+时序回归测试）、
Windows 同端口双绑定（关 reuse + EXCLUSIVEADDRUSE）、客户端伪造 id/ts 覆盖权威戳、
好感度跨 Tab 丢失更新（写前重读）、翻面与动画/情绪 transform 三方互踩（包装层分层）、
散步/摇摆步进可被 setMode/入睡即时掐断、naive 心跳时间戳 500 改安全默认、outbox 5MB 归档、
WAR 收敛为三张在用精灵图、方形图标全套生成、门铃会话自动发现、死代码 MAILBOX_INBOX 通道删除。

**已知未做 / 设计如此（backlog）**：
- UI 尚未迁入 Shadow DOM：宿主页全局样式可能污染气泡字体，反向高 z-index 也可能盖住页面弹窗；
- MV3 长轮询贴线飞行：SW 空闲 30s 回收 vs 挂起 25s，余量仅 5 秒（alarm 看门狗可拉起），
  Chrome 未来调整空闲策略则需改 waitUntil/offscreen 方案；
  聊天同步等待期同理——SW 若被打盹，前端显示"信已投出，回信会自己游回来"，
  服务端照常完成、回信经 inbox 自愈送达（错误已分类：auth/offline/在途）；
- 聊天记录与上下文按 Tab 分片：换 Tab 聊天上下文重置（存储已裁剪至最近 ~12 条）；
- sleepy 深夜困困场景已退役（台词数据保留在 behavior.js 内置词料里）；
- 搭话券的 not_before/expires_at 过滤字段暂无写入方（纯前置校验，无害）；
- ⚠️ 0.4.4 曾把 WAR 收敛为显式中文文件名导致精灵图全拒载（Chrome 不匹配百分号
  编码的非 ASCII WAR 路径），0.4.5 回滚为 `sprites/*.png`；根治方案是精灵图改
  ASCII 文件名（backlog）；
- HOME_URL 仍为绝对盘符路径：工作区搬家后新标签页会落到错误页（无校验指引，待做 SW 启动探测）；
- outbox 归档文件（archive/outbox-*.jsonl）仅冷备，无在线检索工具；
- 无多平台适配器（微信/飞书类 Hermes 式网关属远期议题）、无流式回复；
- 信局随 Harness 会话托管——会话结束信局停 = 本体下值 = 代班顶班，**这是特性不是故障**；
- `chrome://` 页面不注入内容脚本、也无法被中继自动化（扩展重载只能人工）；
- SW 里 taskkill.exe 可能被主机策略拦截，用 `Stop-Process` 替代。
